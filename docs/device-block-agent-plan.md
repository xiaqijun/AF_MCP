# 设备联动封禁智能体计划文档

## 1. 文档概述

本文档用于明确“设备联动封禁智能体”的首版建设目标、功能边界、实施计划与验收标准，作为后续 Python 版 AiPy 智能体扩展开发的执行基线。

当前方案基于 AiPy Pro 智能体扩展机制与 [ip-ban-api.md](ip-ban-api.md) 中已确认的 AF REST API 能力，优先实现“认证主链路 + IP 封禁主链路”，暂不扩展到多设备编排和无关认证配置接口。

## 2. 建设目标

首版智能体目标如下：

1. 接收上游研判智能体输出的威胁结论与处置建议。
2. 将自然语言或结构化研判结果归一化为标准封禁指令。
3. 在执行前完成本地白名单校验与风险控制。
4. 通过 AF 标准 API 执行封禁、删除、清空、查询与时间配置操作。
5. 在执行后自动回检策略状态，返回结构化结果。
6. 记录执行日志，支持后续追溯与人工审计。

## 3. 范围边界

### 3.1 首版纳入范围

首版仅纳入以下能力：

1. 用户登录。
2. token 保活。
3. 用户注销。
4. 查询临时封锁 IP。
5. 查询业务封锁 IP。
6. 新增业务封锁 IP。
7. 删除临时封锁 IP。
8. 删除业务封锁 IP。
9. 清空封锁攻击者。
10. 清空临时封锁 IP。
11. 清空业务封锁 IP。
12. 获取封锁总条数。
13. 获取自动封锁攻击者时间。
14. 修改自动封锁攻击者时间。

### 3.2 首版排除范围

首版明确排除以下内容：

1. 密码策略相关接口。
2. 当前已登录管理员账户权限查询接口。
3. 3A 认证配置接口。
4. WAF、IPS、防火墙等多设备并行编排。
5. 图形化前端页面。
6. 外部日志平台联动。
7. 复杂审批流、工单流和多人会签流。

## 4. 功能需求

### 4.1 指令生成

智能体需要根据研判结果生成标准化封禁指令，至少明确：

1. 封禁对象。
2. 封禁类型。
3. 封禁时长。
4. 目标设备或目标接口。
5. 是否需要人工确认。

输入可为两类：

1. 结构化输入，如威胁等级、IP、端口、建议处置动作、建议时长。
2. 自然语言输入，由智能体内部归一化为标准执行参数。

### 4.2 白名单校验

在任何执行动作前，必须进行白名单强校验，避免误封：

1. 核心业务 IP。
2. 运维网段。
3. 办公网出口。
4. 第三方链路地址。

首版要求：

1. 支持本地配置白名单。
2. 白名单命中后直接阻断执行。
3. 在结果中明确返回命中规则与阻断原因。

### 4.3 指令下发

智能体通过 AF 标准 API 完成封禁下发，首版仅支持：

1. 业务封锁 IP 新增。
2. 业务封锁 IP 删除。
3. 临时封锁 IP 删除。
4. 封锁攻击者/临时封锁/业务封锁清空。
5. 自动封锁时间查询与修改。

### 4.4 执行回检

下发后必须进行回检，确认策略生效。

回检方式至少包括：

1. 重新查询业务封锁 IP 列表。
2. 重新查询临时封锁 IP 列表。
3. 查询封锁总条数。
4. 查询自动封锁时间配置。

### 4.5 日志记录

系统需要记录以下关键过程：

1. 登录与注销。
2. 指令生成结果。
3. 白名单校验结果。
4. 下发请求摘要。
5. 回检结果。
6. 错误信息与失败原因。

首版建议使用本地结构化日志文件或标准日志输出，不强制依赖外部日志平台。

### 4.6 人工确认

高风险动作必须支持人工确认机制。

首版至少对以下动作启用确认：

1. 清空封锁攻击者。
2. 清空临时封锁 IP。
3. 清空业务封锁 IP。
4. 批量删除封禁。
5. 批量新增业务封锁。

### 4.7 模式控制

首版支持两种执行模式：

1. 自动模式：通过全部风控校验后自动执行。
2. 人工确认模式：高风险操作必须显式确认后执行。

## 5. 业务流程

首版标准流程如下：

1. 接收研判输入。
2. 解析并归一化参数。
3. 执行白名单校验。
4. 判断是否需要人工确认。
5. 登录或复用现有 token。
6. 调用 AF API 执行目标动作。
7. 对执行结果进行回检。
8. 记录日志。
9. 返回结构化响应。

## 6. MCP 工具清单

### 6.1 认证工具

1. `auth_login`
   - 用途：登录 AF 设备并建立会话。
   - 输入：`host`、`namespace`、`username`、`password`、`verify_tls`
   - 输出：`token`、`cftoken`、`role`、`namespace`、`authResult`、`passwdStatus`

2. `auth_keepalive`
   - 用途：维持当前登录 token 不超时。
   - 输入：`host`、`namespace`
   - 输出：`success`、`message`、`data`

3. `auth_logout`
   - 用途：注销当前登录状态并清理本地会话。
   - 输入：`host`、`namespace`
   - 输出：`success`、`message`

### 6.2 封禁查询工具

1. `block_list_temp`
   - 用途：查询临时封锁 IP。
   - 输入：`host`、`namespace`、`start`、`length`、`search`、`sortby`、`order`
   - 输出：分页结果对象。

2. `block_list_business`
   - 用途：查询业务封锁 IP。
   - 输入：`host`、`namespace`、`creator`、`start`、`length`、`search`、`sortby`、`order`
   - 输出：分页结果对象。

3. `block_get_total_count`
   - 用途：获取封锁总条数。
   - 输入：`host`、`namespace`
   - 输出：`cnt`

4. `block_get_block_time`
   - 用途：获取自动封锁攻击者时间配置。
   - 输入：`host`、`namespace`
   - 输出：`blockTime`、`bruteBlockTime`、`minutes`

### 6.3 封禁执行工具

1. `block_add_business`
   - 用途：新增业务封锁 IP。
   - 输入：`host`、`namespace`、`src_ips`、`block_time`、`creator`、`aifw_type`、`override`、`result`
   - 输出：新增结果对象。

2. `block_delete_temp`
   - 用途：按条件删除临时封锁 IP。
   - 输入：`host`、`namespace`、`records`
   - 输出：删除结果列表。

3. `block_delete_business`
    - 用途：按条件删除业务封锁 IP。
    - 输入：`host`、`namespace`、`creator`、`records`
    - 输出：删除结果列表。

4. `block_clear_attackers`
    - 用途：清空封锁攻击者。
    - 输入：`host`、`namespace`、`creator`、`confirm`
    - 输出：被清空记录列表。

5. `block_clear_temp`
    - 用途：清空临时封锁 IP。
    - 输入：`host`、`namespace`、`creator`、`confirm`
    - 输出：被清空记录列表。

6. `block_clear_business`
    - 用途：清空业务封锁 IP。
    - 输入：`host`、`namespace`、`creator`、`confirm`
    - 输出：被清空记录列表。

7. `block_set_block_time`
    - 用途：修改自动封锁攻击者时间配置。
    - 输入：`host`、`namespace`、`block_time`、`brute_block_time`
    - 输出：更新后的配置对象。

## 7. 配置项说明

首版建议支持以下配置项：

1. `host`：AF 管理地址。
2. `namespace`：目标命名空间，默认 `public`。
3. `username`：登录用户名。
4. `password`：登录密码。
5. `verify_tls`：是否校验证书。
6. `confirm_mode`：是否启用人工确认模式。
7. `retry_count`：失败重试次数。
8. `whitelist_file`：白名单配置文件路径。
9. `log_level`：日志级别。

## 8. 安全与风控要求

1. 白名单命中必须阻断执行。
2. 清空类和高风险批量操作必须要求 `confirm=true`。
3. 凭证不得明文持久化到日志。
4. Python 服务标准输出只用于 MCP 协议输出。
5. 调试日志必须走 `stderr` 或标准 logging。
6. 登录态失效后需要返回明确错误，并提示重新登录。

## 10. 验收标准

项目通过验收至少满足以下条件：

1. 登录、保活、注销链路可正常运行。
2. 查询、新增、删除、清空封禁链路可正常运行。
3. 自动封锁时间查询与修改可正常运行。
4. 回检逻辑可确认策略是否已生效。
5. 白名单命中后可阻断执行并返回明确原因。
6. 高风险操作在人工确认模式下无法绕过确认。
7. 日志可完整记录关键过程且不泄露敏感凭证。
